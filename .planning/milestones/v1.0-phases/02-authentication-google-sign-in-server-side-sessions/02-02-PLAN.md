<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> api/auth/logout.js | Untrusted client request (session cookie) crosses into server code that deletes a database row |
| Edge (middleware.js) -> origin | Cookie-presence pre-filter only; not a trust boundary for authorization, just a UX short-circuit before the origin serves the static /account page |
| Browser -> googleusercontent.com | Cross-origin image load for the profile avatar, scoped by CSP img-src and referrerPolicy |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-11 | Repudiation / Information Disclosure | api/auth/logout.js | medium | mitigate | Sign-out deletes the DB-side sessions row (not just the cookie), so a captured cookie cannot be replayed after the user believes they signed out (Pitfall 6) |
| T-02-12 | Elevation of Privilege | middleware.js | low | accept | Middleware's cookie-presence check can be bypassed by forging a fake `session=` cookie value, but this only skips the redirect-to-sign-in UX shortcut — the origin page still renders client-side and immediately calls the authoritative GET /api/auth/session, which rejects any cookie without a matching, unexpired DB row (Plan 02-01 Task 2) |
| T-02-13 | Tampering | vercel.json, public/_headers (CSP img-src widening) | low | accept | Widening img-src to `https://*.googleusercontent.com` only allows loading images from that host, not script execution — no XSS/script vector is introduced, and script-src remains unchanged ('self' only) |
| T-02-SC | Tampering | package.json (@vercel/functions install) | high | mitigate | Verified via `npm view` this session: official Vercel first-party package (github.com/vercel/vercel), no postinstall script — same trust tier as the already-installed @vercel/postgres; no blocking checkpoint required |

</threat_model>
