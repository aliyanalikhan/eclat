## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> api/billing/prices.js | Public GET endpoint serving the picker's price facts; untrusted callers may read it, so it must expose only display data (amount/currency/interval) and never price IDs, secrets, or subscription state |
| Browser -> api/billing/status.js | Authenticated GET (session cookie) serving per-user subscription rows to the picker and the success page; unauthenticated callers must get the fail-closed 401 { subscriptions: {} } shape |
| Browser (navigation) -> api/billing/checkout.js | The picker's plain-anchor Subscribe CTA crosses into server code that re-validates the slug and subscription state and creates a real Stripe Checkout Session; the ?checkout_error=1 flag is the only failure signal returned to the picker |
| Browser (client state) -> src/routes/Subscribe.jsx / SubscribeSuccess.jsx | Client-rendered ownership UI and the success view read the same endpoints; this boundary is render-only by design (D-04) — client state is never an entitlement boundary, and only an observed webhook-synced subscriptions row flips success (D-07) |
| Server -> Stripe API (prices.retrieve) | Server-to-server price lookups using the secret key; the prices endpoint must reduce the response to public facts before it crosses back into the browser |
