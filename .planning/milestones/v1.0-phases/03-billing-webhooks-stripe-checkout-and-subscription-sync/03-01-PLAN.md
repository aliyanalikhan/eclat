## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> api/billing/checkout.js | Untrusted client request (`product` query string, `session` cookie) crosses into server code that resolves an allowlist entry and creates a real Stripe Checkout Session |
| Browser -> api/billing/status.js | Untrusted client request (`session` cookie) crosses into server code that reads the authenticated user's subscription rows |
| Stripe (external) -> api/billing/webhook.js | Stripe's hosted delivery of signed events crosses the trust boundary into a public POST endpoint; every byte is unverified until `constructEvent` validates the HMAC signature |
| Server -> Stripe API | Server-to-server Checkout Session creation and price lookups using the secret key; responses are trusted only because the request carried the secret |
| Server -> Postgres (subscriptions/webhook_events) | Server writes subscription state and processed-event ids; a DB leak is mitigated by never storing raw webhook payloads (webhook_events holds only the event id) and by reconciling subscriptions strictly from signed events |
