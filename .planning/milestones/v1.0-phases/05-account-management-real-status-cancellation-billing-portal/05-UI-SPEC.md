# Phase 5 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This phase rebuilds one existing page (`src/routes/Account.jsx`) to show real Stripe-backed data instead of mocks — it introduces zero new routes and zero new visual language. Per the task brief and `05-CONTEXT.md`'s "UI hint: yes — the Account page gets a real rebuild, but visual polish follows the existing design system," this contract's job is to pin down exactly how the existing `.panel`/`.upsell`/`.invoices`/`.demo-notice` component vocabulary extends to cover states that did not exist in the mock: multiple per-product panels (D-02/D-16), a state-aware CTA (D-08), a payment-failed notice (ACCT-04), and a real, sometimes-partially-degraded invoice table (D-04/D-09). No new CSS classes are required — every new surface is built from classes that already exist in `src/styles/eclat.css`.

**shadcn gate — resolved without prompting:** `components.json` is absent and this project has no Tailwind/CSS-in-JS layer (confirmed: plain CSS in `src/styles/eclat.css`, per `CLAUDE.md`'s documented tech stack, and already resolved identically in `02-UI-SPEC.md`/`03-UI-SPEC.md`/`04-UI-SPEC.md`). The task brief for this phase explicitly instructs "lock in continuity with the current visual language rather than introduce a new one" — initializing a Tailwind/Radix component system to rebuild one mocked account page would violate that instruction outright, so the shadcn init prompt was skipped as inapplicable rather than asked. `Tool: none` is correct for this phase, not a placeholder.

## Spacing Scale

This codebase does not use a strict 8-point grid (existing values already in `.panel`/`.upsell`/`.invoice` include 10px, 18px, 20px, 22px, 26px, 28px, 30px). Phase 5 introduces exactly four new spacing decisions — everything else reuses existing values verbatim.

| Token | Value | Usage in this phase |
|-------|-------|-------|
| Per-product eyebrow → its panel | 20px | New — a multiple of 4. Intentionally **not** matching the existing page-level "Account" eyebrow's `marginBottom: 18` (`Account.jsx:67`) — that 18px value is pre-existing chrome this phase does not touch, so it carries forward unchanged and is not a new decision requiring grid alignment. The per-product `.eyebrow` label (product name) this phase introduces above each panel is a genuinely new spacing decision, so it uses 20px to stay on the 4px grid rather than copying the legacy 18px value verbatim. |
| Between stacked per-product panels | 40px | New — when 2+ products are held (D-16), panels stack vertically; 40px sits inside the codebase's existing range (between the 30px panel padding and the 44/48px major-block gaps already used on this page) rather than introducing an outlying value |
| Panel → state-aware CTA row | 24px | New — a multiple of 4. The CTA row (Manage / Subscribe / Update payment method, D-08) is a brand-new phase-5 surface, not a pre-existing box this phase merely leaves untouched — unlike the page-level `h1`/eyebrow chrome, it did not exist before this phase, so its placement is a new spacing decision rather than an inherited one. `.upsell`'s legacy `margin-top: 22px` is **not** reused verbatim here; 24px replaces it to stay on the 4px grid, using the same visual weight class (one step above the 20px eyebrow gap, matching `.upsell`'s existing role as a "next major block" separator) — same discipline applied to the eyebrow-gap fix above. |
| ACCT-04 notice → its panel | 24px | New — a multiple of 4, for the identical reason as the CTA-row token directly above: the payment-failed notice (ACCT-04) is a brand-new phase-5 surface, so its margin-top is a new decision, not an inherited `.upsell` value. Uses the same 24px as the CTA-row token since both occupy the same structural slot (the box directly below a panel) and should read as one consistent gap across every panel, not two different values for visually equivalent positions. |
| Invoice table, rows, "Billing history" heading | inherits `.invoices`/`.invoice`/`.h2` spacing exactly (`margin-top: 24px`, `padding: 18px 0`, heading `margin: 66px 0 0`) | Unchanged — this block is pre-existing chrome this phase does not restructure; column *content* changes (D-11), layout spacing does not, so no new spacing decision is being made here |

Exceptions: none beyond the four new tokens above (eyebrow gap 20px, stacked-panel gap 40px, CTA-row margin 24px, ACCT-04-notice margin 24px) — every other value is reused from the existing `.panel`/`.upsell`/`.invoices`/`.h2`/`.eyebrow` classes, not re-derived. `.upsell`'s legacy 22px is deliberately **not** reused as-is anywhere in this phase's new surfaces.

## Typography

Exactly **4** declared size tiers. The 22px data-value size is explicitly **folded into the Heading tier** (both are `--serif`, weight 400 — the same typographic role rendered at two scales, not a fifth tier). Every value below is an exact px, or a single `clamp()` formula, never a vague range.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Label | 10px (`.panel__key`, notice tag — mirrors `.demo-notice__tag`) · 11px (`.eyebrow`, `.invoice__date`, `.invoice__link`) | 400 | 1 | Uppercase, `.14–.2em` letter-spacing, `--narrow` font |
| Body | 15px | 400 | 1.6 | `.upsell__text`, `.invoice` row text — the single body-copy size this phase's rebuilt surfaces use |
| Fine | 13px (`.fine` — error/degraded fine print, per Copywriting Contract) · 14px (`.demo-notice__text` — reused verbatim, colors overridden via inline style, for the ACCT-04 notice body per Component Notes §3) | 400 | 1.6 | Smaller supporting copy, always `--sans`, never the primary reading size |
| Heading | clamp(30px, 4vw, 52px) — `.h2` "Billing history" section heading, unchanged · **22px** — `.panel__val` data values (Status/Plan/Renews/Card, per-product), folded in here rather than counted separately | 400 | ~1 (heading) / 1 (data value) | `--serif` — the only two serif sizes this page uses |

Weights in use across the whole codebase: **400 (regular, default everywhere)** and 500 (medium, `.wordmark`/`.auth-trigger__name` header chrome only — not touched by this phase). Every new element this phase introduces uses 400 exclusively.

The page `h1` ("Reader since 2021" — clamp(34px, 5vw, 64px), unchanged) is deliberately **not** one of the 4 tiers above: it is pre-existing chrome this phase does not touch and no requirement (ACCT-01..04) touches this line, so it is out of this contract's scope rather than a fifth size decision.

No "loading…" text or spinner is introduced — the existing page-level "Checking your session…" gate (`Account.jsx`, already present) is extended to also cover the new `useAccount` fetch, matching the established silent-gate precedent from `02-UI-SPEC.md`/`04-UI-SPEC.md`.

## Visual Focal Point

- **Multiple stacked product panels (D-16):** the eye lands first on the **top-most panel's Status field** — the `.status-dot` + "Active"/"Past due"/"Canceled" pairing inside the first panel, which is always `eclat-online` per D-16's fixed product order. It is the only colored dot above the fold and the first data point in reading order; no other element on the page (eyebrow labels, CTA buttons, the invoice table below) competes with it for attention.
- **ACCT-04 notice present alongside its panel:** the notice must be the strongest visual pull on the page. Its `var(--bad)` border + tinted background + "Payment failed" tag is the *only* alarm-colored surface anywhere on `/account` (see Color — Destructive), so it draws the eye ahead of the panel's own neutral-ink Status/Plan/Renews/Card values, even though it sits below the panel in document order. A past-due subscriber must register "payment failed" before reading anything else in that product's block.

## Phase-Specific Component Notes

Concrete visual/interaction specs for the rebuilt `/account` page. These are prescriptive — implement as specified, not as a starting point for redesign.

### 1. Per-product summary panels (replaces the single `eclat-online`-only `.panel`, D-02/D-16)

- Render one `.eyebrow` + `.panel` pair **per product the user holds**, in fixed order: `eclat-online`, `eclat-hardcopy`, `book-online`, `book-hardcopy` (D-16's "eclat-online first, then the rest" — this is the exact order `src/data/products.js`'s `PRODUCTS` array already declares). Only render a panel for a product the user actually holds a `subscriptions` row for — no empty/placeholder panels for unowned products.
- Each panel is preceded by an `.eyebrow` label holding the product's display name from `src/data/products.js`'s `productName(key)` (e.g. "Éclat Online", "Children's Book Hard Copy"), at the 20px gap declared in Spacing Scale.
- Each `.panel` keeps the existing 4-field grid (`.panel__key`/`.panel__val` pairs) unchanged: **Status**, **Plan**, **Renews**, **Card**.
  - **Status** — `.status-dot` colored `var(--ok)` + "Active" for `active`; `var(--bad)` + "Past due" for `past_due`; `var(--accent)` + "Canceled" for `canceled`. (Today's binary "Active"/"Free tier" + `--ok`/`--accent` dot becomes this 3-state version.)
  - **Plan** — `{Product Name} — {Monthly|Annual}` (D-13), e.g. "Éclat Online — Monthly", server-derived from `stripe_price_id` via `lib/products.js`; `—` if somehow unresolvable.
  - **Renews** — the `.panel__key` label itself is state-aware (D-14): reads **"Renews"** for `active`/`past_due` (value = formatted date, e.g. "12 Aug 2026"); reads **"Access until"** for `canceled` (value = formatted date, same format). The `.panel__val` text is always just the date — the state lives in the key label, not a compound sentence in the value.
  - **Card** — `{Brand} •••• {last4}` with the brand string title-cased (Stripe returns lowercase, e.g. `visa` → "Visa"), e.g. "Visa •••• 4242" (D-15); `—` when unavailable (no default payment method, or the best-effort Stripe read failed).
- Date formatting (Renews / Access until / invoice dates): match the exact existing mock format **`D MMM YYYY`** (e.g. "12 Aug 2026" — no comma, day before month), the format already used in today's mocked invoice rows (`src/data/content.js`'s `invoices` array) — full continuity, no new date style introduced.
- Currency formatting (invoice amounts): `$` + two decimals, e.g. `$84.00` — Stripe's `amount_paid` is minor units (cents); divide by 100 before formatting. Matches the exact existing mock format.

### 2. State-aware CTA row (D-08)

- Directly below each panel (at the 24px gap declared in Spacing Scale — a new phase-5 decision, not `.upsell`'s legacy 22px), render exactly one primary action reflecting that product's state:
  - `active` or `past_due` → **"Manage"** button, `.btn.btn--sm` (plain ink pill, not `--accent` — this is a neutral management action, not an upsell).
  - No subscription for that product → the generalized no-subscription notice (Copywriting Contract) with the **"Subscribe"** CTA, `.btn.btn--sm.btn--accent`, exactly as today's single upsell block, just with generalized copy.
- Never render a dead-end "Subscribe" CTA for a `past_due` product (this was the Phase 3 WR-01 bug this phase exists to fix) — `past_due` always gets "Manage", paired with the notice below.

### 3. ACCT-04 payment-failed notice

- Only rendered under a `past_due` product's panel, at the 24px margin-top declared in Spacing Scale (a new phase-5 decision, not `.upsell`'s legacy 22px — see Spacing Scale for why this box is treated as new rather than inherited). Structurally a **recolored copy of `.demo-notice`** (`.demo-notice`/`.demo-notice__tag`/`.demo-notice__text` classes reused verbatim, colors overridden via inline `style` — matching the exact Phase 4 precedent of inline-style color overrides over new stylesheet classes, so zero new CSS is added):
  - `border-color: var(--bad)` (was `var(--accent)`)
  - `background: color-mix(in srgb, var(--bad) 7%, transparent)` (was the accent tint)
  - Tag background `var(--bad)` (was `var(--accent)`), tag text unchanged white
- Layout unchanged from `.demo-notice`: tag + body text, `flex`, `gap: 14px`, `align-items: flex-start`.
- Contains the **"Update payment method"** action (`.btn.btn--sm`, plain ink, positioned at the notice's trailing edge — reuses `.upsell`'s existing flex row + button placement pattern).

### 4. Invoice table (D-09..D-12)

- `.invoices`/`.invoice` grid classes unchanged. Column 2 changes from the mock's free-text "desc" to the real **invoice number** (D-11) — update the grid's implicit column semantics but not its `grid-template-columns` values (`150px minmax(0,1fr) 90px 110px`) since the visual footprint must match the mock exactly.
- Column order, left to right: **Date** → **Invoice number** → **Amount** → **Receipt →** (unchanged link copy, now pointing at the real `hosted_invoice_url`, `target="_blank" rel="noopener noreferrer"` per D-11's "opens in a new tab").
- All held products' invoices appear in **one** table, most-recent-first, up to 12 rows (D-10/D-12) — no per-product filtering, no pagination control.
- Zero invoices → the existing `.empty` "No invoices yet." block, unchanged.
- Invoice section unavailable (best-effort Stripe failure, D-04) → the `.fine`/`--bad` message from the Copywriting Contract, replacing the table entirely (not an empty-looking table).

### 5. Zero subscriptions held at all

- If the account has no `subscriptions` rows for any of the 4 products, render no per-product panels at all — just the page's existing "Account" eyebrow + `h1`, followed directly by the generalized no-subscription notice (Copywriting Contract) and its "Subscribe" CTA. The "Billing history" heading and invoice table still render below (a customer can have paid invoices from a subscription that later lapsed to nothing, or simply show the empty state) — do not hide the whole page.

### 6. Page-level loading gate

- Extend the existing `if (loading || entitlementsLoading)` gate in `Account.jsx` to also cover the new `useAccount` hook's `loading` — the page never renders any panel, CTA, or invoice content until session, entitlements, *and* the account fetch have all resolved, exactly matching Phase 4's established "no intermediate flash" rule for this same gate.

### 7. Post-portal-return refresh (D-06)

- No special client-side state is needed: returning to `/account` from the Stripe portal remounts the route, which remounts `useAccount`, which issues a fresh `no-store` request. The page simply re-renders through the same loading → populated flow described above with the new post-action state (e.g. updated card, "Manage" instead of a stale past-due notice) — no toast, no "updated!" banner, no visual diffing against the prior state.
