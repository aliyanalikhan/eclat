**shadcn gate note:** `components.json` was not found. This project has an established, deliberate bespoke design system (1901-line `eclat.css`, editorial serif/narrow-sans type system, custom `--accent`/`--ok` tokens) that predates this milestone and is explicitly the system to *extend, not replace* per project instructions. shadcn was evaluated per protocol and declined — introducing a second component system for one auth header slot would fragment the design language for no benefit. All contract values below extend the existing tokens/classes in `src/styles/eclat.css` rather than inventing new ones.

**CSP dependency (not a UI decision, but a rendering precondition):** the signed-in avatar (see Color/Copywriting below) requires `img-src` in `vercel.json` and `public/_headers` to allow `https://*.googleusercontent.com`, and the `<img>` must set `referrerPolicy="no-referrer"` (RESEARCH.md Pitfall 3). If that CSP change is not shipped in this phase's implementation, the avatar's `onError` fallback (initials circle, see below) is what actually renders — the UI contract holds either way.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between avatar and name text in the signed-in nav label |
| sm | 8px | Gap between disclosure caret and label text; dropdown menu item vertical padding |
| md | 16px | Dropdown menu internal padding; gap between "Account" and "Sign out" rows |
| lg | 24px | Inline error notice top offset below the fixed header; notice internal padding (paired with existing 18-20px `.demo-notice` padding — see Exceptions) |
| xl | 32px | Notice bottom margin before page content resumes |
| 2xl | 48px | not used this phase |
| 3xl | 64px | not used this phase |

Exceptions: the existing codebase does not strictly follow an 8-point scale (e.g. `.nav` gap is `30px`, `.panel` padding is `30px`, `.demo-notice` padding is `18px 20px`). This phase's **new** elements (dropdown menu, inline notice) use the 8-point scale above; where a new element sits directly against an existing near-8pt value (e.g. reusing `.demo-notice`'s `18px 20px` padding for the inline error notice, rather than introducing a new `24px` padding value), the existing value is kept as-is rather than nudging surrounding legacy CSS — see Copywriting Contract for exactly which existing class is reused.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (signed-out nav slot) | "Sign in" — plain text, no "with Google" suffix (space-constrained single nav slot per D-06/D-07); Google's own consent screen carries the "Sign in with Google" branding after the redirect |
| Signed-in nav label | User's Google given/display name, truncated to 18 characters with an ellipsis (max-width ~140px) if longer; falls back to "Account" if the name claim is empty |
| Empty state | Not applicable this phase — no list/collection UI is introduced or modified (the billing-history/invoices empty state on `/account` is pre-existing, unmodified `.empty` copy "No invoices yet." from `Account.jsx`, out of this phase's scope) |
| Error state (failed/denied/cancelled sign-in, D-15) | "Sign-in failed — try again." where "try again" is an inline plain `<a href="/api/auth/google?return_to=…">` link (not a React Router `Link`, per Pitfall 1), reusing the original `return_to` path so retrying preserves context |
| Loading state (header auth slot) | No copy — the slot renders reserved-width empty space (see UI Considerations) rather than a "Loading…" label, to avoid a second visible flicker between "Loading" → resolved state |
| Loading state (`/account` route gate) | "Checking your session…" — centered, `.eyebrow`-styled single line, shown only for the brief window before the client-side session check resolves (replaces D-09's forbidden stale-mocked-page flash) |
| Sign-out in-flight | No copy change — the "Sign out" menu item visually dims/disables (see UI Considerations) rather than swapping to loading text, since the action typically resolves in well under a second |
| Sign-out failure | "Couldn't sign out — try again." — rendered inline inside the still-open dropdown menu, same 14px/`var(--ink-soft)` treatment as the sign-in error notice, no separate page-level banner |
| Destructive confirmation | Not applicable this phase — sign-out has no confirmation step; it is reversible in one click (sign in again) and D-11's multi-device design means it only ever affects the current device's session |

## Phase-Specific Component Notes

Concrete visual/interaction specs for the new elements this phase introduces, extending `src/components/Header.jsx` and `src/styles/eclat.css`. These are prescriptive — implement as specified, not as a starting point for redesign.

### 1. Header auth-aware nav slot (replaces the static "Account" `LINKS` entry)

Three states, same single slot position (last item in `.nav`, before the "Subscribe" button):

- **Loading/unknown** (post-hydration, before `/api/auth/session` resolves): render an empty `<span>` sized to the widest possible resolved label (`min-width: 90px` — enough for a truncated name + avatar) with `visibility: hidden`. This reserves layout space so nothing shifts when the real state arrives; it is intentionally invisible, not a skeleton or spinner, per Copywriting Contract's "no copy" decision.
- **Signed-out**: plain `<a href="/api/auth/google?return_to={current_pathname}">Sign in</a>` using the existing `.link-underline` class exactly like the other `LINKS` items (13px, uppercase, `.09em` letter-spacing, `var(--sans)`) — same visual weight as "Archive"/"Books"/"Writings", not styled as a `.btn`.
- **Signed-in**: a `<button type="button" aria-expanded aria-controls>` disclosure trigger (not an `<a>` — it opens a menu, it does not navigate) containing, left to right: a 20px circular avatar (`border-radius: 50%`, `object-fit: cover`, `referrerPolicy="no-referrer"`), 4px gap, the truncated name label (500 weight, per Typography), 8px gap, a small disclosure caret (new 8×8px inline SVG chevron, `stroke="currentColor"`, rotates 180° via `transform: rotate(180deg)` when `aria-expanded="true"`, transition matches existing `--ease`). Avatar `onError` swaps to an initials-circle fallback: `var(--ink)` background, `var(--bg)` text, the name's first letter, `var(--narrow)` font — same `idle/loaded/failed` state-machine shape as `Cover.jsx`.

### 2. Sign-out disclosure menu

- Anchored directly below the trigger button, right-aligned to it, `4px` gap.
- Surface: `background: var(--paper)`, `border: 1px solid var(--line)`, `border-radius: 4px`, `box-shadow: 0 12px 28px rgba(22,19,15,0.12)` (reuses the shadow feel of `.btn:hover`'s existing shadow value, scaled down), `padding: 8px` (sm token), `min-width: 160px`.
- Two rows, each `padding: 8px 16px` (sm/md tokens): "Account" (`<Link to="/account">`, closes menu on click) and "Sign out" (`<button type="button">`, triggers `POST /api/auth/logout`). 13px/400/`var(--ink)`, hover background `rgba(22,19,15,0.04)` (matches existing `.btn--ghost:hover` background value).
- Open/close mechanics reuse the exact pattern already established in `Header.jsx`'s mobile nav toggle: `aria-expanded` state, closes on `Escape` (returning focus to the trigger), closes on route change, and additionally closes on outside click (new, since the mobile toggle doesn't need this but a dropdown does).
- Sign-out in-flight: the "Sign out" row gets `opacity: 0.5` and `pointer-events: none` for the duration of the request (Copywriting Contract "Sign-out in-flight").
- Sign-out failure: an inline `<p>` appended below the two rows, `font-size: 14px`, `color: var(--ink-soft)`, `line-height: 1.6`, `padding-top: 8px`, `border-top: 1px solid var(--line-soft)` — visually a small addendum, not a redesign of the menu.

### 3. Inline sign-in error notice (D-15)

- Lives in `src/App.jsx`'s shell, rendered once, directly below `<Header />` and above the routed page content — not inside individual route components, since `return_to` can be any page.
- Trigger: the OAuth callback appends `?auth_error=1` to the `return_to` redirect on failure; a shell-level effect checks for this param on mount, shows the notice, then calls `history.replaceState` to strip the param (so a page refresh doesn't re-show it).
- Visual: reuses `.demo-notice`/`.demo-notice__tag`/`.demo-notice__text` classes as-is (accent-colored left accent via the existing border treatment, `color-mix` tinted background, 18px/20px padding) — swap the tag text from "Demo" to "Error" and the body copy to the Copywriting Contract's error string. This is a direct class reuse, not a new pattern.
- Position: `margin: 24px auto 32px` (lg/xl tokens), same `max-width: var(--shell)` / `padding: 0 var(--gut)` horizontal constraint as `.page`, so it lines up with page content below the fixed header (`var(--nav-h)` = 70px is already cleared by each route's own top padding, e.g. `.page--narrow`'s `150px` top padding — the notice sits inside that top padding band, not on top of the header).
- Dismissal: no explicit close button — it is cleared by the `history.replaceState` strip on next navigation/interaction, consistent with D-15's "no dead-end page" framing (it's transient, not a persistent alert the user must act on).

### 4. `/account` route auth gate loading state (D-09)

- Replaces the entire mocked page body (not just a section of it) while `/api/auth/session` is in flight: a single centered `.eyebrow`-styled line reading "Checking your session…", vertically centered in a `min-height: 60vh` container matching `.page--narrow`'s existing `min-height: 100vh` intent without the full page chrome flashing.
- On resolution: signed-in → render the existing (unmodified) `Account.jsx` content; signed-out or check failed → `navigate('/api/auth/google?return_to=/account', { replace: true })`-style full redirect (plain navigation, not React Router `Link`, consistent with Pitfall 1).

## UI Considerations

Applicable state considerations resolved: 8 covered, 1 backstop, 0 unresolved (4 dismissed with reason)

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| loading | header auth-aware nav slot (`nav`, `interactive-control`) | ✅ covered | Renders a reserved-width, invisible placeholder (matches the widest expected label's box) until `GET /api/auth/session` resolves, then fades to the resolved state — no flash between "Sign in" and "Account" text (RESEARCH.md Pitfall 2) |
| error | header auth-aware nav slot | ✅ covered | The header itself carries no separate error UI — a failed sign-in only ever shows the page-level inline notice (see below); the header simply reflects the resulting signed-out state |
| overflow, long-text | header auth-aware nav slot | ✅ covered | Signed-in label truncates the Google display name to 18 characters + ellipsis, max-width ~140px, single line, never wraps or breaks the fixed-height header (see Copywriting Contract) |
| loading | "Sign in" CTA link (`interactive-control`) | ✅ covered | Plain `<a href="/api/auth/google">` triggers a full browser navigation on click; no JS `onClick` handler or spinner is added — the browser's native loading UI is the loading state, and any interception would break the flow per Pitfall 1 |
| error | "Sign in" CTA link | dismissed | Duplicate of the header/nav-slot error row and the inline-error-notice row above/below — a failed attempt is handled entirely by the page-level notice, not by the link itself |
| long-text | "Sign in" CTA link | ✅ covered | Copy is the fixed short string "Sign in" — never dynamic, no truncation risk |
| loading | sign-out disclosure trigger + menu (`interactive-control`) | ✅ covered | The "Sign out" menu item dims/disables for the duration of the in-flight `POST /api/auth/logout` request |
| error | sign-out disclosure trigger + menu | ✅ covered | On request failure the menu stays open and shows the inline "Couldn't sign out — try again." message inside the dropdown (see Copywriting Contract) — it does not close or navigate away |
| long-text | sign-out disclosure trigger + menu | dismissed | Menu items are two fixed short labels ("Account", "Sign out") — never dynamic content |
| overflow, long-text | inline sign-in error notice (`static-content`) | dismissed | Copy is a single fixed short string ("Sign-in failed — try again.") — no user-supplied or dynamic text is ever rendered in this notice, so no truncation/wrap risk exists |
| loading | `/account` route auth gate (`nav`) | ✅ covered | While the session check is in flight, `/account` renders the "Checking your session…" line instead of the pre-existing mocked page content (Pitfall 2 / D-09) |
| error | `/account` route auth gate | 🧪 backstop | If `GET /api/auth/session` itself fails (network/5xx), the gate fails closed — treated identically to a `null`/signed-out response and redirected into sign-in, never left rendering the stale mocked page or a raw error state |
| overflow, long-text | `/account` route auth gate | dismissed | The gate's only visible content is the fixed short "Checking your session…" string — no variable-length content |
