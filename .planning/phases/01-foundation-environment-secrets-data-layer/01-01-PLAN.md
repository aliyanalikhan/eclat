<objective>
Lay the server-side data-access foundation for Éclat: a fail-fast pooled Postgres client, the full 4-table schema as a numbered migration file, and a migration runner wired to run automatically as the first step of every `npm run build`.

This is the tracer slice for Phase 1's data layer — it proves the full path (migration file -> runner -> pooled client -> build-script wiring) end-to-end using the script's own graceful-failure behavior as the verifiable seam, since the real database does not exist yet (that's Plan 02). Nothing in this plan invents a connection string or assumes the database is provisioned.

Purpose: Every later phase (2-5) reads/writes through `lib/db.js` and adds migration files to `migrations/`. Getting this seam right — server-only, fail-fast, no ORM, exact-value-safe — is the foundation everything else builds on (per CONTEXT.md D-01 through D-06).
Output: `lib/db.js`, `migrations/0001_init.sql`, `scripts/migrate.js`, `.env.example`, updated `.gitignore`, updated `package.json` (dependency + build script).
</objective>
